# 第一阶段技术开发文档｜摄像头手势控制 3D 光束最小闭环

配套文档：[项目方案](项目方案.md)、[通用技术栈手册](AI产品Vibe%20Coding通用技术栈手册.md)、[技术适配声明](技术适配声明.md)。

状态：第一阶段主要代码已实现，可本地试用；完整阶段验收仍未完成。正文保留实施规范，已执行结果、必要适配和待验项目见文末补充及产品验收记录。

## 一、阶段目标

完成一条真实链路：用户开启摄像头 → 本地模型识别手部 → 确定性手势规则产生控制信号 → 3D 粒子牵引、聚合、分散与波动 → 页面显示状态，用户可关闭并重新开始。

范围：桌面 Chrome、单人单手、一种青紫色空间光束；基本发光与透视效果；四种手势；相对纵深控制与重校准；摄像头预览及关键点；必要控件；鼠标演示；标准/低画质；异常恢复；自动化与真机验收。

产物：`finger-light/` 可运行项目、README、锁定依赖与模型清单、自动化测试、实际验收记录。鼠标演示用于调试和故障兜底，不能作为摄像头功能通过的依据。

本阶段不做：双手交互、精确测距、多粒子形态、声音、录像导出、登录、云存储、手机完整适配、公开部署以及完整视觉系统。第一阶段代码是后续正式产品基础，不另外创建一次性验收页面。

验收以第十一节为准；性能、阈值及成功次数先按原方案执行并显式标为暂定，实测前不冻结为普适指标。

## 二、技术适配摘要

- 路径：纵向切片，所有终端专属处理位于浏览器。
- 默认：TypeScript、npm、Git、类型检查、ESLint、双层测试。
- 按需：Three.js、MediaPipe、Worker、Vitest、Playwright、轻量本地设置存储。
- 替代：Vite + 原生 CSS 作为单画布应用外壳；无 Python、FastAPI、数据库或 LLM API。
- 解释：本项目核心在视觉模型与空间交互，必须在真实 UI 中验证。识别、规则和渲染仍保持独立模块，纯规则可脱离 UI 测试。

## 三、技术栈与模型

| 部分 | 采用组件 | 使用边界 |
|---|---|---|
| 应用与构建 | Vite、TypeScript、原生 CSS | 一张主页面；不建立通用后台或路由平台 |
| 渲染 | Three.js | TypedArray 粒子状态、批量 Points 绘制、自定义光晕材质 |
| 识别 | Google MediaPipe Hand Landmarker | `@mediapipe/tasks-vision`、VIDEO、numHands=1；模型 `.task` 与 WASM 同源提供 |
| 调度 | Web Worker + 浏览器动画帧 | 推理与绘制分开；至多一帧在途，忙时丢帧 |
| 测试 | Vitest、Playwright | 前者验证规则，后者验证页面与生命周期；真机另验 |

先尝试 Worker 内 GPU delegate，若初始化失败，最多切换一次 CPU；CPU 模式降低识别频率并实测。不得在每一帧无限重建模型。Worker 本身不可用或模型持续失败时进入明确的错误/演示状态，真实交互验收仍记未通过。

依赖开发时选择一个兼容组合并锁定；不在文档中捏造未验证版本。README 记录实际版本，资源清单记录模型的 URL、许可、SHA-256、文件大小和对应 SDK/WASM 版本。模型下载是资源准备，不是上传用户画面。

## 四、环境与配置

环境已在技术适配声明记录：Node 24.19.0、npm 11.17.0、Git 可用。第一阶段不需要 Python 或 API Key。不创建没有用途的 `.env`；所有前端配置均视为公开信息。

集中配置 `src/config.ts`，含 schema 校验与明确单位：

| 配置 | 初值 | 说明 |
|---|---|---|
| modelPath / wasmPath | 同源 `models/`、`wasm/` | 支持构建 base 路径；版本与清单一致 |
| cameraWidth / cameraHeight | 640 / 480 | 理想输入分辨率，不假定摄像头一定提供 |
| detectionHz | 25；CPU 初值 15 | 自适应可降频，记录实际值 |
| pinchEnter / pinchExit | 0.25 / 0.35 | 指尖距离除以掌宽，无量纲 |
| gestureHoldMs | 100 | 候选主状态稳定时间 |
| trackingGraceMs / fadeMs | 250 / 500 | 短暂失踪与撤去控制力时间 |
| waveCooldownMs | 150 | 两次波纹最短间隔 |
| waveSpeedThreshold | 1.2 掌宽/秒 | 暂定触发值，需真机调参 |
| maxSimulationStepMs | 33 | 超长时间步限幅；后台回来重设计时 |
| particleCount | 标准 8,000；低 4,000 | 质量档明确显示，性能记录包含粒子数 |
| pixelRatioCap | 标准 1.5；低 1 | 限制高分屏像素开销 |
| modelInitTimeoutMs / frameTimeoutMs | 20,000 / 2,000 | 超时停止当前识别会话并释放资源 |

纵深映射范围、力场强度、阻尼、速度上限及关节伸展阈值也须进入配置，实施时记录具体初值。所有设置必须为有限数值且位于允许范围，不能从 localStorage 直接信任加载。

以下启动契约已实现，首次使用先按产品 README 准备依赖：

```bash

npm ci
npm run dev -- --host localhost --port 5180 --strictPort
```

首次由开发者生成 package.json 与锁文件；此后使用 npm ci。开发前复查端口；若占用，选择其他空闲端口并更新地址，不终止其他项目进程。

用户操作：安装与启动完成后，在 Chrome 打开报告的 localhost 地址，点击“启用摄像头”，仅在浏览器弹窗中授权。Mac 系统权限未开放时，按实际报错引导到系统设置处理。

## 六、数据、资产与状态

### 数据边界与持久化

视频帧、关键点、速度历史、波纹、粒子位置均仅驻留内存，消费后释放。不录制、不上传、不写入浏览器存储。模型/WASM 为静态资产；测试默认用合成点位，不保存用户录像作为 fixture。

localStorage 仅保存一个小型 JSON 对象：`{schemaVersion:1, quality:'standard'|'low', sensitivity:number, previewVisible:boolean}`。每次完整 setItem 替换；读取检查版本、类型及范围。解析失败回默认并提示；写入失败保持本次会话可用；未知新版本保留原值并使用默认，不擅自覆盖。没有重要业务数据与可恢复长任务；粒子重新初始化属于正常行为。

多标签页各自维护会话，偏好最后一次写入生效；不共享摄像头状态；设备占用按错误处理。重校准参考只保留当前会话，刷新或重新开启摄像头后重设。

### 分层状态机

应用：`idle → starting → running → stopping → idle`；启动/运行失败进入 `error`，可重试或切换演示。独立输入源为 `camera | mouse | demo`，同一时刻只有一个源拥有控制权。

追踪：`loading → ready → tracking ↔ lost`，失败为 `error`，关闭为 `stopped`。没有手仍属于摄像头运行中；不能把“未识别到手”显示成摄像头已关闭。

手势：`idle | attract | scatter | follow`。优先级为有效捏合 > 张开 > 指尖牵引 > 待机；波纹是 follow 下的瞬时事件，不单设互斥主状态。

启动使用唯一 sessionId；每个帧有递增 frameId 和由主线程生成的单调时间戳。关闭后 sessionId 失效，迟到消息不得重启状态；若权限请求迟到返回视频流，立即停止其全部轨道。重复启用按钮不得生成多个模型或流。

隐藏页面时暂停推理和仿真并清空运动历史；返回时重设时钟。点击关闭停止视频轨道、销毁模型/Worker；页面卸载与错误退出同样清理。切换鼠标模式前关闭真实摄像头；仅隐藏预览不会关闭摄像头，UI 必须显示真实设备状态。

### 手势与坐标规则

1. 验证 21 点；归一化掌宽采用 index MCP(5) 与 pinky MCP(17) 的距离，在摄像头像素比例修正后的平面上计算，设置非零下限。捏合采用 thumb tip(4) 与 index tip(8)。
2. 手指伸展根据关节夹角与相对长度判定；拇指单独处理。规则需适应手旋转，不能只比较屏幕 y 值。
3. 相机画面、骨架和控制点共用坐标模块，考虑视频原始宽高、显示区域缩放与裁剪；镜像恰好一次。用归一化屏幕点映射到有界 3D 交互平面。
4. 位移按时间差计算速度，拒绝重复/倒序时间戳；连续位置使用与 dt 相关的平滑。重获追踪的第一帧重置速度，避免触发假波纹。
5. 捏合保持迟滞；候选状态经稳定时间进入。丢失追踪后不再产生事件，最近目标仅短暂保留，再将外力衰减到零。
6. 相对纵深通过首次稳定正对手掌约 0.5 秒的尺度中位数校准；将掌宽比例的对数映射到有界 z。明显侧转、遮挡或退化掌宽时保持/平滑回中，不作为精确测距。提供“重新校准”。
7. 开放手掌的中心用于分散，捏合中点用于聚合，食指尖用于牵引。第二只手出现时不融合点位，按上一帧空间连续性优先保持原控制手，避免切手瞬移。

### 粒子规则

每个粒子保留位置、速度与固定随机相位；基础流场形成光束，叠加局部吸引、排斥和带传播半径的波动力，最后施加阻尼。力在零距离附近软化，速度/加速度限幅，所有坐标必须有限；过远粒子平滑回归或重新生成。

聚合保留光核半径，避免所有粒子塌为一点；分散改变粒子的相对分布，不只是缩放场景；波动必须可见传播和衰减。光晕通过着色器和混合实现，复杂后处理可留后续阶段。

## 七、API / 工具设计

无远程业务 API、SSE 或动态 Agent 工具。以下本地接口必须可独立验证：

| 接口 | 输入 | 输出与校验 |
|---|---|---|
| CameraController.start/stop | 摄像头配置、会话标识 | 有效 MediaStream 或 AppError；停止幂等；晚到流立即释放 |
| HandTracker.initialize/submit/dispose | 模型配置、带 frameId 的 ImageBitmap | 验证后的帧结果或错误；所有分支释放 bitmap；不堆积帧 |
| classifyGesture | 点位、时间戳、上次状态、规则配置 | mode、target、pinch、openness、velocity、wave 事件；非法输入返回安全无控制状态 |
| ParticleField.step/reset | dt、交互状态、种子 | TypedArray 状态；同种子可复现，不依赖摄像头或 DOM |
| SceneRenderer.render/resize/dispose | 粒子缓冲、视口参数 | 画面与资源释放；无 WebGL 时明确错误 |
| SettingsStore.load/save | 版本化偏好 | 合法设置或默认值；存储不可用不导致应用崩溃 |

Worker 消息为判别联合：主线程 `init | frame | dispose`，Worker `ready | result | error`，均携带 sessionId；frame/result 还含 frameId、captureTimestampMs。result 含 hasHand、landmarks、handedness、inferenceDurationMs。无手返回空点位；有手必须恰为 21 个有限坐标。handedness 分数只表明左右手分类，不当作点位置信度。

主线程仅在不忙时提交帧；忙时跳过采样，不留队列。结果若属于旧会话、旧 frameId 或超过新鲜度窗口则释放并忽略。单帧超时后终止该 Worker，进入可重试错误，不能永远卡在 busy。

错误统一为 `{code, message, recoverable}`，诊断信息在受控开发日志中脱敏记录。最低错误码：CAMERA_DENIED、CAMERA_UNAVAILABLE、CAMERA_BUSY、MODEL_LOAD_FAILED、MODEL_INIT_TIMEOUT、TRACKER_FAILED、FRAME_TIMEOUT、INVALID_TRACKING_RESULT、WEBGL_UNAVAILABLE、WEBGL_CONTEXT_LOST、SETTINGS_UNAVAILABLE。

页面只显示可执行提示，如“摄像头未获授权，可重试或使用鼠标演示”。启动资源请求失败允许用户重试；同一启动最多一次自动重试。权限拒绝不自动反复弹窗。WebGL 恢复后重建资源；恢复失败要求重新加载，不标记仍在正常绘制。

## 十、测试要求

### 第一层：自动化规则与集成验证

| 类别 | 必须覆盖 |
|---|---|
| 手势规则 | 0.25/0.35 迟滞；稳定时间；缩放与画面比例归一化；旋转的手；主状态冲突；波纹冷却；捏合拖动不出波 |
| 点位与坐标 | 空手、少点、多点、NaN/Infinity、退化掌宽；镜像恰一次；resize/crop；重复与倒序时间戳；重新追踪速度归零 |
| 纵深 | 校准前/后、重校准、尺度变化限幅、手掌侧转异常；不产生无界 z |
| 力场 | 固定种子聚合半径减小、分散半径增大；波纹传播后衰减；零距离、大 dt、后台恢复均无非有限坐标 |
| Worker | 一个在途帧；旧会话结果忽略；超时释放；初始化失败、CPU 回退失败；重复 stop；bitmap 在错误分支也释放 |
| 摄像头生命周期 | 拒绝、无设备、占用、轨道 ended；重复 start；start 后立刻 stop；迟到授权流回收；切模式与卸载释放 |
| 本地存储 | 缺值、坏 JSON、旧/未知版本、非法范围、写入拒绝、跨标签页偏好冲突 |
| 页面 | 各状态按钮可用性、键盘操作、预览隐藏仍显示设备开启；错误可重试；鼠标四种效果；桌面两宽度控件不遮挡 |

自动化 E2E 可模拟摄像头/Worker，但记录必须注明模拟。类型检查、ESLint、测试和构建均需成功；开发服务器与构建预览均检查模型/WASM 路径，无资源 404。通过断网/拦截资源测试失败提示，不把 npm 安装成功当作模型可用。

### 第二层：真实摄像头与模型端到端冒烟

在实际 Chrome 和普通摄像头中，按第十一节执行真实手势。记录设备、系统/浏览器版本、摄像头实际分辨率、模型哈希、SDK/WASM 版本、推理后端、质量档、光照描述、每次成功/失败与原因。云推理调用费用为“不适用”；不要编造 Token 用量。

性能目标沿用方案：争取 60 FPS；低画质连续运行 5 分钟平均至少 30 FPS，记录低于 24 FPS 的持续区间及原因，不只报告平均值。分别记录标准与低画质；标准不达目标时明确报告，不能隐藏切档。

四种核心手势各 10 次，目标每类至少 9 次达到预期。动作开始到视觉响应目标多数在 150 ms 内；如果有高帧率录像条件，用可观察画面测至少 10 次并注明样本与误差。内部结果年龄、推理耗时不等同物理端到端延迟；无录像/等效测量时将该指标标记待测，保留主观跟手评价。

真实摄像头或用户操作不可获得时：继续完成可执行的自动化测试与错误分支，真实识别/体验记待验，本阶段不得整体标记完成。
